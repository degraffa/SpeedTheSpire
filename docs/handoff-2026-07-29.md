## THE ONE IN-FLIGHT ITEM — Windows CI job (branch `ci-windows`, `1b7893f`)

A `win-debug` job on `windows-2022` with a pinned-toolchain assert. Three runs
failed, each at the assert, each a REAL catch by the pin — full trail:

1. **Run 1** (`cf1e6a7`): bare `clang-cl` resolved to Visual Studio's bundled
   copy — `ilammy/msvc-dev-cmd` prepends VS paths. Fixed: absolute path
   `C:\Program Files\LLVM\bin\clang-cl.exe` in assert + configure overrides.
2. **Run 2** (`5945b25`): the runner image PREINSTALLS llvm via choco, so the
   pinned `choco install llvm --version=22.1.8` said already-installed, exited
   0, installed nothing; the assert refused the image's own LLVM. Fixed:
   `--force --allow-downgrade`.
3. **Run 3** (`1b7893f`): still the assert. Root cause found post-run, NOT yet
   fixed on the branch: **the chocolatey feed has no llvm 22.1.8** — verified
   via the community API; newest 22.x is **22.1.7**. The forced install fails,
   and the failure is INVISIBLE because the step's last command is
   `pip install pyyaml`, which succeeds (a multi-line pwsh step reports only
   the last command's exit code). Two defects, two fixes needed:
   - Make the install step fail loudly: check `$LASTEXITCODE` after each choco
     command (or one command per step).
   - Resolve the version gap. The local byte-identity proof (20 fixture traces
     hash-identical vs GCC/Clang) was made at **clang-cl 22.1.8**. Options:
     (a) **RECOMMENDED: install the exact 22.1.8 from the official LLVM GitHub
     release** (winget `LLVM.LLVM --version 22.1.8`, or the release-asset
     installer via direct URL, silent `/S`) — keeps the proven toolchain and
     the assert untouched; (b) pin choco's 22.1.7 AND re-prove the fixture
     hashes under 22.1.7 locally first, then move the assert — do not loosen
     the assert to a range without that proof (the pin's whole purpose; see
     the workflow's own comments and the Windows-CI obligations row).
   The job's cache/configure/test steps have never executed — expect ordinary
   iteration there once the toolchain lands (the win presets themselves are
   proven locally; `tests/host_shell.hpp` and `tools/fuzz` headless handling
   landed in wave 2 specifically for CI-shaped environments).

When green on the branch: merge `ci-windows` → `master`, confirm the combined
